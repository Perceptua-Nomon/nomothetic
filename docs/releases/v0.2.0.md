# nomothetic v0.2.0

**Released:** 2026-03-11
**Type:** Feature release

---

## Summary

Feature release adding DC motor control (Phase 6) and high-level vehicle
convenience API (Phase 7). Motors are controlled via the `HatClient` and
exposed through REST endpoints. Vehicle commands (`drive`, `steer`,
`pan_camera`, `tilt_camera`) provide convenient abstractions over low-level
channel indices—the daemon configuration maps channels to physical actuators.
Grayscale sensor support added for line-following and obstacle detection.

---

## Features

### Phase 6: Motor API Endpoints

#### New `HatClient` Methods
```python
def set_motor_speed(channel: int, speed_pct: float, ttl_ms: int = 500) -> None
def stop_all_motors() -> int  # Returns count of stopped motors
def get_motor_status() -> MotorStatusResult
```

#### New REST Endpoints
| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/hat/motor` | Set single motor speed (-100–100 %) |
| POST | `/api/hat/motor/stop` | Stop all motors immediately |
| GET | `/api/hat/motor/status` | Query active motor TTL leases |

#### Response Models
- `MotorRequest`: channel, speed_pct, ttl_ms (with validation)
- `MotorResponse`: channel, speed_pct, timestamp
- `StopMotorsResponse`: stopped count, timestamp
- `MotorStatusResponse`: active_leases array with channel/ttl_remaining_ms/conn_id
- `MotorLeaseItem`: Single lease entry with metadata

### Phase 7: Vehicle Convenience API

High-level vehicle commands that abstract away channel-to-peripheral mappings.
The daemon config determines which channels control drive motors, steering servo, etc.

#### New `HatClient` Methods
```python
def drive(speed_pct: float, ttl_ms: int = 500) -> None
def steer(angle_deg: float, ttl_ms: int = 500) -> None
def pan_camera(angle_deg: float, ttl_ms: int = 500) -> None
def tilt_camera(angle_deg: float, ttl_ms: int = 500) -> None
def read_grayscale() -> GrayscaleResult  # { channels: [0,1,2,3], values: [...] }
```

#### New REST Endpoints
| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/drive` | Set vehicle forward/backward speed |
| POST | `/api/steer` | Set steering angle |
| POST | `/api/camera/pan` | Pan camera servo |
| POST | `/api/camera/tilt` | Tilt camera servo |
| GET | `/api/sensor/grayscale` | Read grayscale line sensors |

#### Request/Response Models
- `DriveRequest`: speed_pct, ttl_ms (optional, default 500)
- `DriveResponse`: speed_pct, motors (count), timestamp
- `SteerRequest`: angle_deg, ttl_ms
- `SteerResponse`: angle_deg, timestamp
- `CameraRequest`: angle_deg, ttl_ms
- `CameraResponse`: angle_deg, timestamp
- `GrayscaleResult`: channels (list), values (list)
- `GrayscaleResponse`: channels, values, timestamp

## Validation & Error Handling

### Request Validation (Pydantic)
- `channel`: 0–3 (4 motors max)
- `speed_pct`: -100.0–100.0 (inclusive)
- `angle_deg`: -180.0–180.0 (vehicle-dependent; daemon validates)
- `ttl_ms`: 100–5000 (milliseconds)

### HTTP Status Codes
- `200 OK` — Success, response includes `timestamp` (ISO 8601 UTC)
- `422 Unprocessable Entity` — Validation error (bad type, out-of-range, missing field)
- `500 Internal Server Error` — HAT daemon hardware error (I2C, I/O)
- `503 Service Unavailable` — Daemon not running or connection broken

## Compatibility

### With nomopractic
Requires **nomopractic ≥ v0.2.0** for motor and vehicle IPC methods.
- v0.2.0 IPC schema adds: `set_motor_speed`, `stop_all_motors`, `get_motor_status`, `drive`, `steer`, `pan_camera`, `tilt_camera`, `read_grayscale`
- Daemon returns `UNKNOWN_METHOD` for incompatible clients
- REST endpoints return `503` if daemon is running v0.1.x and method not found

### Python Version
Requires Python ≥ 3.9. Tested on 3.9, 3.10, 3.11, 3.12.

### Dependencies
No new required dependencies.
- Optional: `paho-mqtt` for telemetry (already listed in `[telemetry]` group)

---

## Breaking Changes

None. All motor and vehicle endpoints are purely additive. Existing camera,
streaming, and HAT servo endpoints remain unchanged.

---

## Migration

1. **Upgrade nomopractic to v0.2.0** first (daemon handles `/api/hat/motor` and vehicle IPC methods)
2. **Then upgrade nomothetic to v0.2.0** (`pip install --upgrade nomothetic[api,pi,web,telemetry]`)
3. Optionally configure motors and vehicle mapping in daemon `config.toml`
4. Restart both services: `sudo systemctl restart nomopractic`, then `systemctl restart nomothetic`

## Configuration

Motor and vehicle behavior is configured in the **`nomopractic` daemon**, not nomothetic.
Example (`/etc/nomopractic/config.toml`):

```toml
motors = [
  { pwm_channel = 12, dir_pin_bcm = 24, reversed = false },  # Motor 0
  { pwm_channel = 13, dir_pin_bcm = 23, reversed = false },  # Motor 1
]
motor_default_ttl_ms = 2000

servos = [
  { ttl_ms = 500, neutral_us = 1500 },  # Servo 0 (steering)
  { ttl_ms = 500, neutral_us = 1500 },  # Servo 1 (pan camera)
  { ttl_ms = 500, neutral_us = 1500 },  # Servo 2 (tilt camera)
]
```

Vehicle command mappings (which motor/servo does `drive` use?) are implicitly
defined by daemon config order. Consult [docs/hat_ipc_schema.md](https://github.com/Perceptua/nomothetic/blob/main/docs/hat_ipc_schema.md) for full schema.
